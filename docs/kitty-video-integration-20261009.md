# 视频上游、自动定价与无限画布使用说明

2026-10-09，来源 codex。双站生产版 `2.9.9-kitty.10`，画布 `v0.8.0-kitty.2`。

## 管理员配置

1. 打开后台「视频上游与定价」(`/admin/video-upstream`)。
2. 在账号管理中配置算力视频上游，在分组管理中建立或选择余额计费的视频分组。上游 Key 只填入本站后台。
3. 设置「生成每秒加价」「参考每秒加价」「每条加价」，选择自动同步、跟涨、跟跌开关并保存。金额沿用本站视频余额口径，不额外自动换汇。
4. 同步上游目录，选择视频分组并导入所需型号；在上游账号模型白名单中开放对应型号。保留原有配置的旧型号不会自动变成统一视频型号。
5. 用选定型号验证生成、金额、参考素材和下载，再向客户开放。目录显示「协议参数可用」不代表该型号已完成真实生成验收。

默认自动同步关闭，跟涨开启、跟跌关闭，同步间隔 60 秒。加价默认零，管理员应按自己的经营规则填写。全局开关与每个型号的自动跟价配置共同决定是否更新；单型号可以覆盖全局规则。修改加价后，需同步或导入使新规则进入分组价格。正在执行的任务使用提交时价格快照。

按秒模型：生成秒数 ×（上游生成秒价 + 生成每秒加价）；按条模型：上游每条价 + 每条加价。仅已核实参考视频另收费的型号再加：计费参考秒数 ×（上游参考秒价 + 参考每秒加价）。按条和生成秒价不会重复相加；不再叠加旧分组倍率。不同分辨率使用各自价格。

价格同步读取 `https://suanliai.top/api/pricing`。失败或单型号缺价时保留最后有效价格，继续接单；这符合本次选择，但不能保证在上游改价与本站下一次成功同步之间完全没有价差。计费规则变化而不能可靠解析时保留原价并显示错误，不猜测新价。

## 扣费与素材

- 新统一视频任务提交时预扣，成功结算，不重复扣费；明确失败后退款。提交结果不明时保留任务继续核实，不盲目重发或退款。
- 余额和 API Key 额度使用幂等账务；旧任务保留旧账务逻辑。
- 默认每用户视频并发 2，临时素材每用户 256 MB、单站总计 2048 MB，后台可修改。
- 临时参考素材默认保留 24 小时：未使用素材按上传时间计算，已使用素材在最后关联任务结束后继续保留 24 小时，在途任务持续保护。
- 成片从上游 HTTPS 链接直接下载，不在 OVH 永久保存。上游存储时限和链接有效期由供应商决定；刷新失效链接不等于延长文件保留时间。
- 本站 API Key、Cookie 不随下载请求发送到上游。浏览器 CORS 或上游 Range 不支持时会显示错误，不悄悄改用 OVH 代理整段成片。

## 客户与无限画布

主站「应用中心」「视频任务」及「无限画布」沿用本站身份和 API Key。画布通过主站「进入无限画布」按钮进入，入口携带版本参数，避免 CDN 缓存旧首页。

画布融合上游正式 v0.8.0 与之后主分支三项改动，保留 Kitty 登录、余额、模型与 Key 选择。项目与素材仍按用户保存在本机浏览器，应定期导出；未启用原版第二套账号、余额或云同步。原版自定义参数翻译在 Kitty 模式禁用，防止绕过本站报价协议。

## 外部工作流

本站视频分组 Key 使用 `Authorization: Bearer <本站 Key>`。以 `https://kittyapi.xyz` 或 `https://kittyyyds.xyz` 为站点根地址，避免把 `/v1` 重复拼接。

| 操作 | 接口 |
| --- | --- |
| 获取有权限的模型及能力 | `GET /v1/models` |
| 预估费用，不创建任务 | `POST /v1/videos/quote` |
| 上传临时参考素材 | `POST /v1/video-references` |
| 创建视频 | `POST /v1/videos`，或 `/v1/videos/generations` |
| 查询原任务 | `GET /v1/videos/{id}` |
| 获取交付内容 | `GET /v1/videos/{id}/content` |

示例请求体（型号与参数以实际开放目录为准）：

```json
{
  "model": "实际开放的型号",
  "prompt": "傍晚海边，镜头缓慢推进",
  "seconds": 5,
  "resolution": "720p",
  "aspect_ratio": "16:9",
  "images": [],
  "videos": [],
  "audios": []
}
```

创建时带稳定的 `Idempotency-Key`，网络超时后重用原键；取得任务 ID 后轮询原任务，不重新生成。查询返回 `delivery_mode=upstream_direct` 且已完成时，可使用 HTTPS `url` 下载；供应商临时链接应作为敏感链接保管。

支持 JSON，以及相同字段的 multipart URL 表单。实际文件需先上传 `/v1/video-references`，再把返回链接放入图片、视频或音频数组。要求原生 OpenAI 文件直传、专有字段或固定返回格式的第三方 SDK，仍可能需要一个适配节点；不能宣称所有工作流不改配置即可通用。

## 验收边界

切换使用新旧实例并存，旧实例有在途请求时保留。未承诺整个切换期间绝对零网络错误。回退不能整库覆盖当前交易；存在新预扣任务时必须保留新版结算能力，不能直接退回旧版账务程序。
