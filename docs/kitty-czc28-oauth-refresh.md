## 管理员怎么用

- 普通 OAuth 账号升级后自动生效，没有必须新开的开关；正常账号不必集体重新登录，客户端地址、API Key 和模型调用方式不变。
- 日常继续正常使用。需要手动维护时使用原有“刷新令牌”入口；它与后台和请求刷新共用互斥/条件写入机制，不要反复并发点击。
- 同一用户、同一工作区且身份信息可确认时，正常 token 轮换可保留会话连续性。
- 在一条本地账号记录上换登录用户、换工作区或重新授权为另一身份后，新开客户端会话；不能借旧 `previous_response_id` 续接，也不能仅改邮箱等显示字段来冒充换授权。
- 修改代理后，旧在途刷新不得覆盖新配置；旧路由请求的自动恢复会停止，后续请求从当前配置重新开始。不是保证在途请求无条件无缝继续，也不需要为此清冷却或放宽限流。
- 持续 401、明确 refresh token 无效/被撤销时仍需核对权限并重新授权。有限恢复不是无限重刷，不会把真实拒绝变成可用。
- 资料不完整而无法确认身份的旧导入记录不猜测继承关系；必要时重新授权补齐并新开会话。
- VM2/母子/影子、PAT、Agent Identity 保留各自原有机制。VM2 的凭据由其登录服务管理，不由普通 OAuth 刷新器代管。
- 同一上游 refresh token 重复导入多条本地账号记录，不保证跨记录互斥；避免依赖这种重复导入防冲突。
