# Kitty QQ 进群消费审核

后台路径：QQ 机器人 → 群管理 → 对应群策略 → 进群自动审核。默认关闭，按群独立保存，沿用群配置模块版本冲突检查。

开启前由群主在 QQ 设置中填写入群问题，将机器人设置为群管理员，并在 QQ 开放平台订阅 `GROUP_MEMBER_EVENT (1<<24)`，取得入群申请审批接口权限。网站不会修改 QQ 群问题。后台填入相同的问题文字、最低累计消费和拒绝原因。

示例：问题“请输入累计消费满10元的用户邮箱”，门槛 `10`，拒绝原因“本群只审核已消费用户”。金额直接比较后台累计实际消费，不进行人民币/美元换算，不以充值或当前余额代替消费。累计消费来自 `qq_bot_usage_metrics` 对 Kitty 永久请求计量的只读投影，排除标记为无效的指标。

处理新收到的官方签名入群申请：

- `admin_review_qa` 精确匹配后台配置的问题，读取唯一答案；`verify_message` 接受一条仅包含注册邮箱的验证消息。邮箱去除首尾空白并按站点账号规则忽略大小写，不接受多个邮箱或姓名包裹格式。
- 找到唯一有效账号且累计实际消费大于等于门槛，使用 `approve` 同意；账号不存在、停用/删除、消费不足或明确的邮箱答案格式错误，使用 `decline` 拒绝，提交配置的 `reject_reason`，明确不加入黑名单。
- 缺少对应问题、申请信息不完整、超过30分钟、账号归属有歧义、查询失败、QQ权限/接口异常或频率预算用尽，保留人工核对。QQ 已自动通过的事件不再审批。
- 规则按机器人、环境、群和完整规则签名绑定入队。排队时关闭/修改规则或更换环境将取消旧任务；开启以前的事件不会补批。
- 同一申请使用稳定事件键去重，提交前持久预留一次尝试。QQ 超时可能已执行，不自动重试。记录区分正在提交、成功同意/拒绝、取消和待人工核对，不把接口失败报告成已拒绝。

填写邮箱只能核验所填账号的资格，不能证明申请人拥有该邮箱。此功能不自动绑定 QQ 账户、不发奖励、不开放该邮箱的账户信息；如需防止借用他人邮箱进群，需另做登录后的一次性申请码或绑定身份校验。

不使用聊天模型进行邮箱或消费审核。只向 QQ 的审批接口提交申请 ID、动作和通用拒绝原因，不发送群消息或主动私聊。申请答案沿用现有任务临时载荷，完成后清空；运行记录只保存动作和原因码，不保存邮箱或具体消费金额。

使用现有 settings、qq_bot_jobs 和永久用量视图，无新增数据库迁移。代码回退可以恢复原版本，不应回灌历史账务数据库。
