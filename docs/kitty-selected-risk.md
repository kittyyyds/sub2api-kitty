# Kitty 精选风控与 0.2.3 升级

日期：2026-09-09。来源：codex。

本版基于官方 v0.2.3，精选移植 zuchengchen/sub2api 的远程审核与证据联动。保留原内容审核、Prompt Audit，以及站点既有支付、赠金、Kitty Apps、媒体、分组、模型展示、Kitrty 检测等功能。

## 两个独立开关

管理员进入「加强风控」（`/admin/kitty-risk-control`）：

- 「加强审核」控制请求前的关键词与远程供应商审核。
- 「证据归档与联动」控制新模块的加密归档、违规记录、自动处置和请求终止。可以单独开启以接收上游 cyber_policy 证据；该模式可能立即禁用命中用户或管理员的相关 Key，务必先配置邮箱白名单。

首次上线和升级到不同版本或源码提交时，两个开关强制复位为关闭。供应商配置、白名单和历史证据保留。管理员必须在当前版本显式打开并保存；同一版本及同一提交的普通重启保留手动设置。禁止改回从旧版本继承启用状态。

关闭时不发出新的审核请求，不新增本模块的归档、封禁或请求终止；已经发出的网络请求或已经完成的处置无法撤回。保存后本进程立即生效，其他进程或直接修改数据库的状态最多一秒同步。本模块开关不改变原内容审核、Prompt Audit 的独立配置。

## 建议启用顺序

1. 两个总开关先保持关闭，配置适用分组、模型、关键词、远程审核渠道及邮箱白名单。密钥在后台填写，不写入源码。
2. 将第二层设为 Shadow（观察），打开「加强审核」并保存，再测试所配供应商。总开关关闭时，供应商测试同样禁止发起网络调用。
3. 观察供应商可用性与结果。需要保留审核记录时，再独立打开「证据归档与联动」。开启后检查自动封禁、违规次数、邮件和白名单设置。
4. 确认远程供应商及共识条件就绪后，将第二层切为 Enforce。该模式会阻断不符合规则的请求；供应商不可用时按页面配置处理，可能影响请求成功率。

远程审核会消耗所配置供应商的额度，并增加命中审核流程的延迟。这是站内风险管理功能，不能证明或保证上游模型身份，也不保证改善模型能力。

## 归档与恢复

新设置为 `kitty_risk_config`，新数据库表以 `kitty_risk_` 开头，与原审核隔离。完整对话分片加密；列表保留脱敏的命中摘要。归档密钥位于应用定价数据目录下的 `kitty-risk/keyring.json`，生产应落在 `/app/data` 持久卷。该私有文件必须随数据卷备份保管，禁止进入 Git。

密钥丢失时不得生成替代密钥覆盖历史归档。加密失败仅保存内容丢失标记和最小元数据，不把正文或其 Base64 写入应急文件。历史访问审计保留。代码回滚不反向执行数据库迁移。

## 保留与删除范围

- 删除 Cursor 添加账号、验证/同步和专用转发；历史字段不作破坏性删除。主站 Shark 转接服务在生产验收后停用并保留恢复材料。
- 删除 GPT Model Variant Lock 及其 Sol/Terra/Luna 强制改写。普通模型映射、工具调用和 WebSocket 行为保留。
- Luna 默认每百万 Token：输入 $0.40，输出 $2.40，缓存写 $0.50、读 $0.04；priority 为两倍。Astra 默认输入 $10、输出 $50。管理员显式覆盖、渠道价格和分组倍率仍按原优先级生效。
- 不引入 SVIP、冻结 $100、会员折扣或专属模型体系；不额外移植 fork 的其他网关策略。
