# GPT 指纹配置使用说明

这是一组按账号开启的客户端身份与连接对照配置。它不会证明上游采用了什么风控算法，也不保证提高模型质量或额度。未开启时沿用账号原设置。

## 入口与测试

后台“账号管理”，GPT OAuth 账号操作栏点击“指纹配置”。列表姓名旁显示已保存的默认/Mac/Linux/Windows 标签。选中多个账号后可点击“批量设置指纹”；非 GPT OAuth 账号和凭据影子账号不参与。

打开“启用独立方案”，选择身份后保存。新建账号也可直接选择预设。新增配置与原有“指纹收敛”相互独立，默认保留原有收敛模式；不要为了切换操作系统声明而修改会话或完全收敛。

第一次对照只改身份，连接设置全部沿用现有。同一模型、思考强度、题目、出口和并发条件下重复测试，再单独比较连接模板。每分钟请求数、请求间隔及账号业务并发均保持原有逻辑。

## 配置范围

| 设置 | 含义 |
| --- | --- |
| 默认/Mac/Linux/Windows | 修改 User-Agent 中声明的系统、架构和终端；版本、originator 同源配套。不是改变实际服务器系统。 |
| 客户端版本 | 留空使用全局生效版本；指定版本至少满足本版兼容门槛。登录授权和令牌刷新仍沿用全局身份。 |
| 语言 | 设置 Accept-Language；留空保留原处理。语言不是时区。 |
| HTTP 版本 | 沿用现有、HTTP/1.1、HTTP/2 协商。WebSocket 升级握手独立使用 HTTP/1.1。 |
| TLS 模板 | 使用依赖库里的 Chrome/Firefox/Safari 握手参数，经 HTTP/1.1 适配；并非官方 Codex 操作系统抓包样本。自定义 TLS 与 HTTP/2 不可同时选择。 |
| 连接复用 | 沿用现有、复用、为新请求创建连接。WS 已有续聊仍保留绑定连接。 |
| 高级连接池 | 总连接数、空闲连接数、空闲超时；0 沿用原值。低连接上限可能造成等待，连接数与业务请求并发不是同一个数值。 |
| WebSocket 重试 | 调整失败后的重试等待和总预算；不改变正常请求的发送间隔。 |

启用独立方案的账号明确使用内置 GPT 转发，不经过外部 OAuth 传输插件，确保连接配置实际由本服务执行。关闭后回到原有插件/内置路径选择。自定义 TLS 要求目标 HTTPS；不会在失败时绕开已选代理直连。

配置用于后续请求/新连接；正在处理的请求正常完成，已有 WS 续聊保留原 socket。切换方案后用新会话进行对照，以免把旧连接的行为误认为新方案。原有模型、思考强度、工具关联、鉴权凭据、计费和配额均不由本功能改写。

## 出口信息

单个账号面板中点击“重新检测”。有多个代理时先选择一个已绑定代理。检测通过该代理访问出口查询服务，失败时不回退直连。没有代理时检测服务器实际出口。

保存出口 IP、地区、可获得的 IANA 时区、检测时间及配置绑定摘要。代理配置变化后旧观测失效。结果只表示检测时的该条线路，不证明所有后续模型请求使用相同 IP；动态代理和按目标分流的代理可能不同。时区明确标为“推断、未发送”，没有加入虚构的时区请求头。

## 停用与回滚

先关闭“启用独立方案”并保存，账号恢复原有客户端与连接配置。若另行改过原有指纹收敛，按原值恢复。

本次没有新增数据库迁移。应用版本回滚使用该站点上一版不可变镜像与 Compose，只重建应用服务，不恢复旧数据库、不重建 Redis。具体源码压缩包、镜像 ID、恢复目录和校验值见本次发布记录。
