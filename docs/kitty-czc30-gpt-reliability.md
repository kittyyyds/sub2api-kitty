## 这批包含什么

| --- | --- |
| 1. Chat 安全断流恢复 | 仅未执行、未交付且未取消的合格 OAuth 请求可有界恢复；已输出、真实用量、工具执行和强续接不重放。 |

| 3. HTTP 200 JSON 错误 | 识别真正错误包，向客户端交付错误并保留真实用量；不将取回 HTTP 200 当业务成功。 |

## 管理员怎样使用

### 自动重置卡

在“账号管理”中，OpenAI OAuth 母账号的额度操作旁可见“自动用重置卡”。
点击开启，确认弹窗会显示当前 5 小时、7 天阈值及自动耗卡提示；确认后开启。
编辑账号也需要先确认，再保存修改。关闭无需二次确认，已提交到上游的用卡操作不会被撤回。

“额度耗尽时使用点数”是另一项既有开关，不与重置卡混用。
自动用卡开启或两分钟内仍有 checking/resetting 尝试时，禁止另行手动重复用卡。
管理员暂停、账号冷却、代理和分组不因切换这个开关被重置。

旧配置显示“尚未重新确认”时，有效状态是关闭。普通编辑、克隆、批量 extra 更新不能悄悄补确认。
只接受数值版本 1；字符串 "1" 和布尔值不算确认。

快捷接口（仅正常管理员权限，不新增受限管理员 Key 的耗卡权限）：

```http
POST /api/v1/admin/accounts/:id/auto-reset-credit-enabled
Content-Type: application/json

{"enabled": true}
```

此接口只更新 auto_reset_credit_enabled 与 auto_reset_credit_opt_in_version，
不把读取时的阈值或 worker 状态整份写回。

### GPT 套餐筛选

账号列表的“所有 GPT 套餐”可筛选五档。Pro_100 / pro100 归 Pro 100，
ChatGPT Pro / pro200 归 Pro 200，pro500 归 Pro 500。
列表、精简列表、采购倍率列表、按筛选导出、跨页批量选择保留同一筛选上下文。
显式选中 ID 的导出按选中项处理。影子账号无独立套餐或仅有空白时继承仍有效的母账号套餐；
已删除母账号不会被拿来补套餐。不会把每页取回后客户端隐藏误当服务端分页筛选。

### Chat Completions 原生状态续接

此项是会话状态保真优化，不是票池、不代替 OAuth 登录，也不保证模型回答质量。
只针对合格普通 Codex OAuth，排除 VM/VM2、PAT、Agent 及旧 BPS 身份。
已有健康账号无需为本批升级集体重新登录。

继续使用既有服务器配置 openai_native_reasoning_replay_config。默认 mode=off。
按用户灰度的例子如下；ID 必须换成实际允许的用户 ID，不能由客户端请求开启：

```json
{"mode":"replay","model_user_ids":{"gpt-6.1-sol":[123]}}
```

客户端仍调用 /v1/chat/completions，发送完整历史，并为同一对话提供稳定 session/thread：

```json
{
  "model":"gpt-6.1-sol",
  "messages":[{"role":"user","content":"示例"}],
  "client_metadata":{"session_id":"session-example","thread_id":"thread-example"}
}
```

也兼容已有 session-id / thread-id 和受支持的 Codex turn metadata。
prompt_cache_key、单独 turn_id 或只有父线程均不构成可复用会话。
不同线程、用户、Key、账号主体、模型或历史改变时安全未命中；普通同主体令牌刷新可保持归属。
只发布完整成功且已经交付的状态，失败和取消不能产生成功续接记录。
