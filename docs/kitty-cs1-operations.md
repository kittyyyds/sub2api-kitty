# CS1 上游管理与运营面板适配

2026-11-06。参考实际部署于 cs1.kittyapi.xyz 的 ZayuAPI v0.2.202，commit `fd8c91e8554528c57be7f2eeb2cf7dfc40d94dcc`。来源与许可证见 `third_party/zayuapi/`。

## 使用流程

1. 后台「上游管理」添加服务提供商，填写站点首页、Sub2API/New API 平台、登录授权、充值倍率和备注。列表展示余额、消费、最后同步时间；同步失败保留上次观察值。
2. 「账号管理 → 添加账号 → API Key → 从服务商导入」选择服务商和上游 Key。名称、地址、倍率自动带入。浏览器只获得 Key 元数据，完整密钥由服务器取得。也可在该选择器中创建上游 Key。
3. 服务商卡片「采购成本」关联现有账号、登记实际支付与购入/赠送额度、设置模型采购规则。已有复杂采购与对账页面作为辅助入口保留。
4. 后台「运营面板」查看汇总、分组与模型、用户排行/明细、趋势、充值订单和只读风险观察。

## 数据口径

- 同一请求优先使用最新登记账单金额，其次为冻结的采购估算，最后为该请求保存的账号成本与账号倍率。修改当前倍率不会重算历史请求。
- CNY 成本需保存对应 USD 汇率；缺少汇率保持未知。未知成本不显示完整毛利，不能当成零成本。
- 总用户消费来自永久用量记录；分组、模型和用户明细来自仍保留的 usage_logs。页面展示明细最早保留日期。
- 今日估算毛利为用户消费减去对应上游成本与监控费用，不等于现金净利润。订阅现金、退款、税费和运营固定费用不在此指标中。
- 用户充值卡统计首次 completed_at 入账的 USD 额度，并排除订单生成的 PAY-* 兑换重复。未入账的 PAID 订单不计入；退款不在此卡扣减。
- 风险观察只读取已有订单与日志，不新增封禁、限流或影响客户兑换的行为。

## 运维与安全

- 服务商配置按条保存至私有 settings，带修订号并在事务内同时保存供应商/钱包。更新使用 CAS；删除仅清除连接授权并留存采购账务和业务账号。
- 上游授权经现有固定加密密钥加密；公共设置和服务商 DTO 不包含授权正文。上游的地址校验和重定向边界沿用主站现有策略。
- 刷新使用受管主实例的既有后台周期：每站最短十分钟、每轮最多三站、单站超时二十五秒。备用实例不运行后台同步。
- Sub2API 的一次性 Refresh Token 在保存/刷新时轮换并落库；测试登录不消耗它。只填 Refresh Token 时应直接保存。
- 不新增数据库迁移，不修改模型转发、客户价格/余额或现有账号调度。只有管理员主动导入账号时才建立对应账号与采购绑定。

## 验证

相关前端交互、服务商协议/令牌轮换与隔离 PostgreSQL/Redis 集成测试覆盖原子保存、CAS、账号绑定回滚、冻结成本、缺汇率、账单优先和充值去重。真实服务商的登录与 Key 创建仍取决于管理员填写的上游站点授权及该站实现。
