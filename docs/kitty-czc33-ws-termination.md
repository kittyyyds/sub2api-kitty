## 图像流异常收尾

适用场景是 HTTP `/v1/responses` 流式入站、内部通过 WS 请求上游，已观察到图像输出，此后上游异常中断且没有终态。客户端仍可写且请求未取消/到期时，补发一次 `response.failed`，保留原响应 ID 和此前图像。已发出的 HTTP 200 不会被伪改成新的 HTTP 状态；协议终态和运维记录会表明这次逻辑失败。

Kitty 原有普通元数据仍按 token 门槛缓冲，本批只让已完成的图像输出及时放行，以便正确识别图像送达后的取消与写入失败。取消、超时、下游写入失败、已有上游终态和策略拦截沿用原有边界，不重复补写。已经有实际进展的请求不重新执行。图像及上游报告的真实用量仅结算一次，不添加估算费用，也不把部分输出当成完整成功。

Kitty 自身的断流错误分类与缓存用量证据解析继续保留；不能用作者通用错误覆盖本地分类，也不能以最后一帧的全零用量抹掉此前已观察到的真实用量。

## 断流诊断

HTTP → WS 的既定不可重试读取退出，可在原有运维错误 JSON 中携带 `stream_read_diagnostic`，其 `replay_boundary` 包含：

- `upstream_progress_observed`：上游是否已有实际进展。
- `client_output_started`：本次读取退出前，是否成功向客户端写出输出。
- `terminal_seen`：是否见到真实上游终态；本地补发失败帧不算。
- `usage_source`：上游显式报告用量时为 `upstream`，未观察到用量时为 `absent`；真实零用量与缺失用量分开。
- `retry_requested`：该退出是否要求重试；本修复路径保持 `false`。

诊断只在既有监控过滤、错误分类和用量处理之后附加到已选中的运维行，不新增错误行、不触发新的错误规则、不增加重试或收费。记录本次账号和代理归属，不记录请求正文、原始异常、握手请求标识、授权材料。原生 WS、多轮其他 turn、请求级错误、取消及本地模型配置错误不借用该快照。

已有序列化 JSON 的原字节与裁剪计数保留；现有原始事件/JSON 优先级、16 条正文窗口、256 条事件和 512 KiB 预算继续生效。队列重复序列化不重复附加。

## 如何使用

发布成功后自动生效，无需重新导入账号、授权、创建 API Key 或打开新开关。遇到目标断流，可在原有运维记录查看失败终态与这五项边界；旧记录缺字段仍表示未知。

新增模型目录测试覆盖账号分组可见性、缓存权限和调度回退，不修改生产权限或调度规则。本批采用本地合成上游和隔离环境验收，不发送收费模型请求。它能改善异常收尾和排障，无法消除外部网络中断、账号权限或容量问题，也不承诺回答质量提升。
