# Kitty 永久充值赠送兼容及活动切换

日期：2026-09-26；来源：codex。本目录 SQL 是独立待执行活动操作，不随应用启动自动修改活动。

## 数据语义与保护范围

- `validity_days = 0` 表示永久赠送；正数仍表示付款履约时起算的有效天数。
- 新永久 `recharge_bonus_grants.expires_at = NULL`；有限期历史记录完全保留原值。不是人为填写一个很远的日期。
- 订单创建时保存金额、赠额、有效期快照。活动切换仅影响切换后新建订单，已创建但尚未支付的旧订单依然按原快照履约。
- 汇总包含永久余额；`next_expires_at` 仅返回仍生效的有限到期时间。永久余额没有最近到期时间。
- 消费和批量冻结优先使用最近到期的有限赠额，永久赠额最后使用。批量释放会归还未使用永久赠额；过期有限赠额不归还。
- 永久赠额仍然受同一订单去重、已使用额度及退款上限保护。永久不代表不能按原退款规则撤销。
- 不修改历史订单快照、已有赠额、历史余额、已有到期时间；保留原有 300 元活动规则。

## 发布顺序

1. 备份数据库并准备带本兼容能力的回退镜像；回退镜像可保留旧 UI，但必须保留永久赠送后端逻辑。
2. 发布包含 `254_recharge_bonus_permanent.sql` 与永久赠送代码的应用。迁移只放宽 `validity_days >= 0` 和允许空到期时间，不改金额或历史数据。
3. 验证应用、支付参数与迁移通过后，独立执行 `20260926-permanent-campaign.sql`。SQL 在事务内备份原活动规则，锁定活动表，更新 30/50/100/500/1000/5000 六档；5/10 不赠送；300 不动。
4. 复查活动 API 返回六档 1/1.99/4.99/29.99/49.99/249.99 且 `validity_days=0`。只读核对原订单快照和赠额数量/到期没有改动。

## 回退边界

- 尚未执行活动 SQL、也未出现任何零天快照或空到期赠额时，旧镜像仍可安全读取原有数据；宽松 schema 可以保留。
- 一旦出现永久订单快照或赠额，禁止直接切回不支持零天/NULL 的旧后端：它会跳过赠送履约、遗漏永久赠额，或在批量结算扫描 NULL 时失败。
- 此时回退 UI/功能必须使用“旧 UI + 永久赠送兼容补丁”的镜像，保留迁移 254。
- 若要撤销本次活动，执行 `20260926-revert-campaign.sql`，恢复被修改的原活动规则；新建档位只禁用不删除，保护外键。已有永久订单/赠额仍永久，不撤销、不改余额。
- 活动备份表仅含非敏感活动配置。重复应用/重复回退均幂等；已经回退的活动不允许直接重新应用，避免复用陈旧备份。
- 手工修改过活动配置后，要先复核原始备份与当前配置再回退；回退 SQL 会恢复备份中的所辖档位。
- 不提供会把 NULL 改成假到期日、回写历史余额或删除历史快照的降级 SQL。
